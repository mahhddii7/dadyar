# داده‌یار ۰٫۲ — دستیار تحلیل مستند فایل‌ها

داده‌یار فایل‌های انتخاب‌شده را مرجع پاسخ قرار می‌دهد. مدل زبانی سؤال را تحلیل می‌کند و برای خواندن سند یا محاسبه روی جدول، ابزارهای محدود سمت سرور را فراخوانی می‌کند. محاسبهٔ عددی با کد انجام می‌شود؛ مدل اجازهٔ اجرای کد دلخواه، SQL یا دسترسی به فایل انتخاب‌نشده را ندارد.

## اجرا در ویندوز

پیش‌نیاز: Node.js 22 LTS یا بالاتر. در CMD داخل پوشهٔ پروژه:

```bat
copy .env.example .env.local
npm ci
npm run dev
```

اگر `.env.local` از قبل وجود دارد، آن را با فایل نمونه جایگزین نکنید. برنامه در `http://127.0.0.1:3000` باز می‌شود. برای دریافت ارتقای مخزن، پس از رسیدگی به تغییرات محلی:

```bat
git pull --rebase origin main
npm ci
npm run dev
```

اگر برنامه قبلاً اجراست، ابتدا با Ctrl+C متوقفش کنید. در حالت production محلی: `npm run build` و سپس `npm start`.

## تنظیم مدل

فقط در `.env.local`:

```env
AI_PROVIDER=openai-compatible
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=
AI_MODEL=
AI_MAX_STEPS=7
AI_JSON_MODE=false
DATA_DIR=./data
```

کلید و نام دقیق مدل را از پنل سرویس خود وارد کنید. سرویس‌های سازگار با OpenAI با آدرس پایهٔ خودشان قابل استفاده‌اند. مدل باید دستورهای فارسی و خروجی JSON را خوب پشتیبانی کند؛ کیفیت پاسخ به مدل انتخاب‌شده نیز وابسته است. `AI_JSON_MODE=true` فقط برای سرویس‌هایی است که `response_format: json_object` را می‌پذیرند. پس از تغییر تنظیمات برنامه را دوباره اجرا کنید. دکمهٔ «تست اتصال مدل» یک درخواست کوتاه واقعی به سرویس می‌فرستد و ممکن است هزینهٔ جزئی API داشته باشد.

برای Ollama، `AI_PROVIDER=ollama` و `OLLAMA_BASE_URL` و `OLLAMA_MODEL` را تنظیم کنید. در حالت `none` یا قطع سرویس، برنامه به‌روشنی اعلام می‌کند تحلیل زبانی تکمیل نشده و در صورت امکان فقط شاخص‌های محاسبه‌شده را ارائه می‌دهد.

کلید را داخل `.env.example` قرار ندهید؛ این فایل در Git ثبت می‌شود. `.env.local` و پوشهٔ `data/` از Git مستثنا هستند. برای خطای `SELF_SIGNED_CERT_IN_CHAIN` باید گواهی ریشهٔ معتبر شبکه در Node مورد اعتماد قرار گیرد؛ `NODE_EXTRA_CA_CERTS` را پیش از اجرای Node در محیط سیستم تنظیم کنید. خاموش‌کردن اعتبارسنجی TLS راهکار پروژه نیست.

اگر آزمون `node --use-system-ca ...` روی ویندوز به پاسخ HTTP می‌رسد، برای اجرای خود برنامه با همین گزینه، ابتدا اجرای قبلی را متوقف کنید و در همان CMD اجرا کنید:

```bat
set "NODE_OPTIONS=%NODE_OPTIONS% --use-system-ca"
npm run dev
```

خطای ۴۲۹ به تفکیک نوع پاسخ سرویس نمایش داده می‌شود: `insufficient_quota` و کدهای اعتبار/سقف هزینه نیازمند بررسی Billing یا سقف مصرف همان حساب و پروژه هستند؛ تکرار خودکار ندارند. محدودیت موقت نرخ با دو تلاش مجدد و فاصلهٔ افزایشی مدیریت می‌شود. اگر `Retry-After` وجود داشته باشد، فاصلهٔ اعلام‌شده رعایت می‌شود؛ فاصلهٔ بیشتر از ۱۵ ثانیه به کاربر اعلام می‌شود و خودکار تکرار نمی‌شود. مهلت کلی درخواست همچنان برقرار است. خطای ناشناختهٔ ۴۲۹ به‌عنوان کمبود اعتبار قطعی معرفی نمی‌شود. متن خام خطای سرویس نمایش داده نمی‌شود تا کلید یا محتوای فایل احتمالی افشا نشود.

اگر سرویس شما OpenAI است، حساب و اعتبار API در [پنل Billing](https://platform.openai.com/settings/organization/billing/overview) و سقف‌ها در [Limits](https://platform.openai.com/settings/organization/limits) مدیریت می‌شوند؛ صورتحساب API از اشتراک ChatGPT جداست.

## فایل‌ها و حفظ داده

- جدول: XLSX، XLSM، CSV، TSV، JSON، JSONL و NDJSON.
- سند: PDF متنی، DOCX، TXT، MD و LOG.
- تصویر: PNG، JPG/JPEG و WEBP با تنظیم OCR زیر؛ صفحات PDF فاقد متن نیز از همین مسیر خوانده می‌شوند.
- فایل‌های قدیمی XLS/DOC، PPTX، فایل فشرده، صوت و ویدئو مستقیماً پشتیبانی نمی‌شوند؛ آن‌ها را به قالب مناسب تبدیل کنید. فایل خراب یا رمزدار ممکن است قابل استخراج نباشد و خطا به تفکیک فایل اعلام می‌شود.
- حداکثر ۱۰ فایل در هر بار بارگذاری، ۳۰ فایل انتخاب‌شده در هر سؤال، ۲۵ مگابایت هر فایل، مجموع ۱۰۰ مگابایت، ۱۰۰ هزار ردیف جدول، ۵۰۰ ستون و ۱٫۵ میلیون نویسهٔ متن. دادهٔ بیش از سقف به‌صورت ناقص ذخیره نمی‌شود؛ باید تقسیم شود.
- شیت‌ها و آرایه‌های مستقل JSON جدا حفظ می‌شوند. فیلدهای تو در توی شیء JSON با مسیر نقطه‌ای قابل پرسش‌اند؛ آرایه‌های داخل سلول کامل حفظ می‌شوند اما خودکار به چند ردیف تبدیل نمی‌شوند.
- CSV چندخطی، جداکننده‌های رایج، سرستون تکراری و ستون اضافه کنترل می‌شوند. برای فایل بدون سرستون یا دارای عنوان چندسطری، فرض تشخیص سرستون را در پیش‌نمایش بررسی کنید.
- مقادیر خالی، عدد نامعتبر، کلید تکراری و فرمول Excel بدون نتیجهٔ ذخیره‌شده گزارش می‌شوند. فرمول یا کد داخل فایل اجرا نمی‌شود.
- خطای یک فایل مانع ثبت فایل‌های معتبر دیگر نمی‌شود؛ فایل‌های ناموفق در پنل خطا باقی می‌مانند.

اصل فایل‌های جدید در `data/originals/` و دادهٔ استخراج‌شده در `data/sources/` نگه‌داری می‌شود. گزینهٔ «دریافت اصل فایل مرجع» در پیش‌نمایش موجود است. حذف فایل، اصل و دادهٔ استخراج‌شده را حذف می‌کند. فهرست منابع در `data/index.json` است؛ فهرست خراب بی‌صدا با فهرست خالی جایگزین نمی‌شود.

برای فایل‌های نسخهٔ قدیمی، اصل فایل در دسترس نیست. اگر هشدار بریدگی یا استخراج ناقص دارند، آن‌ها را حذف و دوباره بارگذاری کنید تا از استخراج جدید استفاده شود.

## OCR اختیاری

```env
AI_OCR_ENABLED=true
AI_VISION_MODEL=
```

نام یک مدل واقعاً دارای قابلیت بینایی را وارد کنید. OCR فعلاً برای ارائه‌دهندهٔ `openai-compatible` پیاده شده است و تصویر کامل یا تصویر صفحهٔ اسکن‌شده به همان API ارسال می‌شود. سقف تصویر OCR ده مگابایت و سقف PDF دوازده صفحهٔ نیازمند OCR است. اگر OCR فعال نباشد، فایل نیازمند آن با پیام مشخص رد می‌شود. نتیجهٔ OCR نیازمند کنترل با اصل فایل است؛ خواندن تصویر تضمین بدون خطا ندارد. جدول تشخیص‌داده‌شده برای محاسبه نگه‌داری می‌شود؛ بخش ناخوانا و استخراج نامطمئن علامت می‌خورند.

PDF و Word متنی بر پایهٔ متن استخراج‌شده پاسخ داده می‌شوند؛ تصاویر، نمودارها و جدول‌های پیچیده ممکن است کامل بازسازی نشوند. برای محاسبهٔ دقیق جدول، XLSX/CSV یا JSON رکوردی مناسب‌تر است.

## روش تحلیل و ارجاع

1. مدل فهرست جدول‌ها، شیت‌ها و ستون‌های منابع انتخاب‌شده را می‌بیند.
2. با ابزارهای `profile`، `query`، `compare`، `read_document` و `search_documents` شواهد تهیه می‌کند و در صورت لزوم ابزار دیگری اجرا می‌کند.
3. عملیات جدولی روی همهٔ ردیف‌های محدودهٔ درخواست اجرا می‌شوند. محدودیت نمایش ۱۰۰ ردیف نتیجه، محاسبه را محدود نمی‌کند؛ نتیجهٔ کامل مرحله برای مرحلهٔ بعد قابل استفاده است.
4. جمع، میانگین، حداقل/حداکثر، شمارش ردیف و مقدار یکتا، گروه‌بندی چندستونی، فیلتر، رتبه‌بندی، ستون محاسباتی و اتصال با کلید یکتای مقصد پشتیبانی می‌شوند. اتصال مبهم و ستون نامعتبر رد می‌شوند.
5. اختلاف تاریخ با تقویم صریح شمسی یا میلادی و بر حسب روز تقویمی محاسبه می‌شود. روز کاری و تعطیلات محاسبه نمی‌شوند. مقدارهای نامعتبر و فاصله‌های منفی پنهان نمی‌شوند.
6. پاسخ به شواهد `[R1]` و ... ارجاع دارد. شمارهٔ ارجاع کنترل می‌شود و عددی که در شواهد نیست، برای اصلاح به مدل بازگردانده می‌شود. این کنترل جایگزین قضاوت انسانی دربارهٔ معنای ادعا، رابطهٔ علت و معلولی یا مبنای تجمیع نیست.
7. برای سندها، بخش و صفحه در صورت وجود مشخص می‌شود. اگر فقط بخشی از سند خوانده شده باشد، پاسخ نشان محدودیت دارد. کل متن ذخیره می‌شود، اما لزوماً در هر سؤال همهٔ آن به مدل ارسال نمی‌شود.
   فایل یا شیت انتخاب‌شده‌ای که در شواهد پاسخ استفاده نشده باشد نیز صریحاً فهرست می‌شود.
8. اگر تعریف شاخص، کلید اتصال، واحد اندازه‌گیری یا معنای ستون مبهم باشد، برنامه باید سؤال روشن‌کننده بپرسد. فایل‌های انتخاب‌نشده در دسترس ابزارها نیستند.

هر درخواست حداکثر ۲۰ اجرای ابزار، ۷ دور مدل به‌صورت پیش‌فرض و ۱۸۰ ثانیه بودجه دارد. رسیدن به سقف یا قطع سرویس، با پیام محدودیت همراه است؛ یافتهٔ ناقص نباید پاسخ قطعی معرفی شود. سابقهٔ حداکثر ۸ پیام از همین جلسه و همین مجموعهٔ فایل‌ها برای فهم سؤال پیگیری فرستاده می‌شود. تاریخچهٔ گفتگو در مرورگر حافظه‌ای است و با تازه‌سازی پاک می‌شود؛ فایل‌ها باقی می‌مانند.

نمونهٔ سؤال‌ها:

- «از این فایل‌ها چه الگو و مشکل کیفیت داده‌ای می‌فهمی؟»
- «مجموع مبلغ را به تفکیک تیم خرید محاسبه و از زیاد به کم مرتب کن.»
- «دو فایل را با کلید شناسه تطبیق بده؛ تعداد اختلاف‌ها و موارد فقط موجود در هر فایل را بگو.»
- «میانگین فاصلهٔ تاریخ شروع تا تاریخ تأیید به روز تقویمی شمسی چقدر است؟ چند تاریخ نامعتبر یا خالی است؟»
- «در سند انتخاب‌شده دربارهٔ شرایط تحویل چه نوشته شده؟ صفحه یا بخش مربوط را ذکر کن.»

برنامهٔ اختصاصی واگذاری ساختمان/طبقه همچنان وجود دارد: با دادهٔ ظرفیت و افراد، یک سیت برای هر نفر و جابه‌جایی آزاد فرض می‌شود؛ هزینهٔ اجاره و هم‌مکانی واحدها نیازمند تعریف جدا هستند. فونت وزیر به‌صورت محلی از `public/fonts` خوانده می‌شود.

## حریم داده و آماده‌سازی برای سرور

در حالت ابری، سؤال، سابقهٔ محدود همین منابع، ساختار فایل و نتیجهٔ ابزارها شامل آمار یا گزیدهٔ ردیف‌ها/متن به سرویس تنظیم‌شده ارسال می‌شود. اصل فایل فقط برای OCR تصویر به شکل تصویر ارسال می‌شود. کلید فقط سمت سرور خوانده می‌شود. داده‌ها در دیسک رمزگذاری نشده‌اند.

این نسخه برای استفادهٔ محلی تک‌کاربره روی `127.0.0.1` است. دسترسی اینترنتی یا چندکاربره به احراز هویت، مجوز هر فایل، جداسازی کاربران، پایگاه‌داده، صف پردازش، ثبت رویداد و سیاست نگهداری نیاز دارد. قرارداد `SourceRepository` برای تعویض مخزن محلی جداست؛ این موارد با تغییر hostname به‌تنهایی فراهم نمی‌شوند.

## آزمون و ساخت

```bash
npm test
npm run lint
npm run build
npm run test:integration
```

آزمون‌های واحد روی استخراج، محاسبات، اتصال، تاریخ، صحت ارجاع و ذخیره‌سازی اجرا می‌شوند. آزمون یکپارچه، مسیر واقعی HTTP برنامه را با سرویس مدل شبیه‌سازی‌شده بررسی می‌کند؛ شامل محاسبهٔ همهٔ ۲۰۸ ردیف دو فایل و اصلاح عدد نادرست مدل. این آزمون هزینهٔ API ندارد و کیفیت معنایی مدل واقعی یا OCR واقعی را تضمین نمی‌کند. برای ارزیابی مدل انتخابی خود، چند فایل با پاسخ معلوم را نیز بررسی کنید.

ساختار اصلی: `src/server/ingestion` استخراج، `analysis/tools` ابزارهای محاسباتی، `analysis/workflow.ts` گردش تحلیل، `ai` ارتباط مدل، `storage` فایل‌ها، `components` رابط و `tests` آزمون‌ها.
