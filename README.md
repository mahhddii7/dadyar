# داده‌یار — دستیار تحلیل فایل

نسخهٔ اولیهٔ یک ابزار محلی برای بارگذاری فایل، پرسش‌وپاسخ مستند و تحلیل داده‌های جدولی. رابط و API در یک برنامهٔ Next.js هستند؛ استخراج فایل، ذخیره‌سازی، اجرای محاسبات و اتصال مدل در ماژول‌های جدا قرار گرفته‌اند تا بعداً قابل‌تعویض باشند.

## اجرای محلی

پیش‌نیاز: Node.js نسخهٔ ۲۰٫۹ یا بالاتر. مستندات [ارتقای Next.js 16](https://nextjs.org/docs/app/guides/upgrading/version-16) حداقل نسخهٔ Node را مشخص می‌کند.

ابتدا فایل تنظیمات را بسازید. در **Command Prompt ویندوز**، داخل پوشهٔ پروژه:

```bat
copy .env.example .env.local
```

در **PowerShell**:

```powershell
Copy-Item .env.example .env.local
```

در macOS/Linux:

```bash
cp .env.example .env.local
```

در صورت اتصال ابری، کلید API را در `.env.local` طبق بخش بعد وارد کنید. سپس:

```bash
npm install
npm run dev
```

سپس `http://127.0.0.1:3000` را باز کنید. برنامه عمداً فقط روی همین دستگاه گوش می‌دهد. برای اجرای نسخهٔ production محلی:

```bash
npm run build
npm start
```

## اتصال مدل ابری سازگار با OpenAI

پروژه از API سازگار با قالب OpenAI استفاده می‌کند؛ بنابراین می‌توانید OpenAI یا سرویس‌های سازگار مانند آروان را انتخاب کنید و برای مدل ابری نیازی به نصب Ollama نیست. نام مدل و نشانی API را از پنل همان سرویس بردارید.

1. از سرویس‌دهندهٔ انتخابی یک کلید API بگیرید.
2. در Command Prompt، از پوشهٔ پروژه دستور `notepad .env.local` را اجرا کنید؛ در PowerShell هم می‌توانید فایل را با Notepad باز کنید.
3. `AI_BASE_URL`، `AI_API_KEY` و `AI_MODEL` را بر اساس اطلاعات همان سرویس تنظیم کنید. برای نمونه، قالب OpenAI به این صورت است:

   ```env
   AI_PROVIDER=openai-compatible
   AI_BASE_URL=https://api.openai.com/v1
   AI_API_KEY=کلید_شخصی_شما
   AI_MODEL=نام_دقیق_مدل_از_پنل_سرویس
   ```

   برای آروان نیز همین سه مقدار را با نشانی پایه، کلید و نام مدل ارائه‌شده در پنل آروان جایگزین کنید؛ پروژه به مسیر `/chat/completions` و احراز هویت Bearer سازگار با OpenAI متصل می‌شود.

   اگر از نسخهٔ قبلی فایل `.env.local` دارید، مقدار `AI_MODEL` آن را هم با نام دقیق مدل سرویس‌دهنده بررسی کنید.

4. اگر برنامه باز است، آن را متوقف و دوباره اجرا کنید تا تنظیم جدید بارگذاری شود.

کلید فقط در کد سمت سرور استفاده می‌شود و `.env.local` از Git مستثناست. کلید را داخل کد، مرورگر یا چت قرار ندهید.

فایل اصلی به API بارگذاری نمی‌شود. برنامه برای ساخت برنامهٔ تحلیل، سؤال، نام فایل‌ها، نوع فایل، نام ستون‌ها، نام شیت‌ها و تعداد ردیف‌ها را می‌فرستد. برای پرسش از سند متنی، گزیده‌های مرتبط (حداکثر ۸ بخش، هرکدام تا ۱۲۰۰ نویسه) ارسال می‌شوند. برای پرسش آزاد از جدول، حداکثر ۶۰ ردیف مرتبط، هرکدام تا ۱۲۰۰ نویسه، به مدل فرستاده می‌شود و اگر همهٔ ردیف‌های لازم در شواهد نباشند، برنامه پاسخ را محدود اعلام می‌کند. در خلاصه‌سازی، حداکثر ۵ ردیف نمونه از هر جدول و تا ۱۵۰۰ نویسهٔ آغازین هر سند به مدل فرستاده می‌شود. محاسبات عددی و تطبیق دو جدول روی داده‌های ذخیره‌شدهٔ محلی انجام می‌شوند.

صورتحساب، سقف مصرف و محل پردازش داده تابع سرویس‌دهنده‌ای است که انتخاب می‌کنید؛ پیش از استفاده، تنظیمات حساب و سیاست دادهٔ همان سرویس را بررسی کنید.

اگر می‌خواهید متن فایل‌ها از دستگاه خارج نشود، می‌توانید به‌جای سرویس ابری از Ollama استفاده کنید: مدل را نصب و اجرا کنید و `AI_PROVIDER=ollama` را در `.env.local` بگذارید. برای محاسبات عددی پایه و نمایش ساختار فایل‌ها، وجود مدل زبانی لازم نیست.

## فایل‌های قابل‌بارگذاری

- جدول‌ها: XLSX، XLSM، CSV و JSON
- اسناد متنی: PDF، DOCX، TXT و MD
- در هر نوبت حداکثر ۱۰ فایل و در هر تحلیل حداکثر ۳۰ منبع؛ سقف هر فایل ۲۵ مگابایت، حجم مجموع هر نوبت ۱۰۰ مگابایت، و سقف استخراج جدول ۱۰۰٬۰۰۰ ردیف است.
- در PDF اسکن‌شده که لایهٔ متن ندارد، OCR هنوز پیاده‌سازی نشده است.
- فایل‌های JSON و CSV با توجه به محتوای واقعی‌شان تشخیص داده می‌شوند؛ اگر پسوند با محتوا نخواند، برنامه هشدار می‌دهد.
- اگر JSON چند آرایهٔ مستقل داشته باشد و یک جدول اصلی روشن نباشد، برای جلوگیری از حذف داده‌ها به‌صورت سند نگه داشته می‌شود و در پیش‌نمایش هشدار می‌گیرد.
- پیش‌نمایش، تعداد ردیف و هشدارهای استخراج از بخش منابع در دسترس‌اند.

## روش پاسخ‌گویی

1. فایل‌های جدولی به ردیف و ستون تبدیل و در مخزن محلی ذخیره می‌شوند؛ متن اسناد هم استخراج می‌شود.
2. فایل‌ها یک‌بار بارگذاری می‌شوند و تا زمان حذف در پروژه باقی می‌مانند؛ هر پرسش با منابع انتخاب‌شده برای همان نوبت تحلیل می‌شود. پاسخ از دانش عمومی مدل ساخته نمی‌شود؛ اگر فایل‌ها دادهٔ کافی نداشته باشند، برنامه باید کمبود را اعلام کند.
3. مدل، در صورت فعال‌بودن، سؤال را به برنامهٔ محدود و اعتبارسنجی‌شده‌ای مثل شمارش، جمع، میانگین، جست‌وجو، پاسخ بر پایهٔ ردیف‌های جدول یا مقایسه تبدیل می‌کند. SQL یا کد دلخواه مدل اجرا نمی‌شود.
4. محدودهٔ فایل و ستون‌ها کنترل می‌شود؛ اگر چند فایل هم‌زمان پاسخ‌گو باشند و معلوم نباشد کدام مدنظر است، برنامه می‌پرسد به‌جای اینکه داده‌های نامرتبط را بی‌صدا با هم ترکیب کند.
5. عملیات عددی روی ردیف‌ها در سرور برنامه محاسبه می‌شوند؛ مدل اعداد را تولید نمی‌کند. مقایسهٔ دو جدول بر پایهٔ کلید مشترک انجام می‌شود؛ کلیدهای تکراری از تطبیق خودکار کنار گذاشته می‌شوند تا ردیف اشتباه به هم وصل نشود.
6. برای سندهای متنی، بازیابی واژه‌ای BM25 بخش‌های مرتبط را رتبه‌بندی می‌کند. پاسخ به فایل و بخش متن ارجاع می‌دهد؛ در جدول‌ها نیز نام فایل، شیت و ردیف نمایش داده می‌شود.

## ساختار پروژه

```text
src/
  app/                 صفحه و Route Handlerهای API
  components/          رابط کاربری: گفتگو، فهرست منابع، پیش‌نمایش
  server/
    ai/                ارائه‌دهندهٔ Ollama و API سازگار با OpenAI
    analysis/          ترجمهٔ پرسش، محاسبهٔ قطعی، ساخت پاسخ و ارجاع
    ingestion/         استخراج فایل‌های صفحه‌گسترده و اسناد
    storage/           قرارداد مخزن داده و آداپتر JSON محلی
```

داده‌های استخراج‌شده در پوشهٔ `data/` کنار پروژه می‌مانند و در Git نادیده گرفته شده‌اند. نسخهٔ فعلی برای استفادهٔ محلی تک‌کاربره است؛ حساب کاربری، نقش‌ها، جداسازی tenant، ثبت ممیزی، OCR، جست‌وجوی برداری و تاریخچهٔ دائمی گفتگو ندارد. برای انتقال به سرور، آداپتر `SourceRepository` را با PostgreSQL یا پایگاه‌دادهٔ مناسب جایگزین کنید، فایل‌ها را در object storage بگذارید، مسیر استخراج سنگین را به worker صف‌دار منتقل کنید، و پیش از دسترسی شبکه‌ای احراز هویت، مجوزهای فایل، سیاست نگهداری و ثبت رویدادها را اضافه کنید. `Dockerfile` برای ساخت production و نگه‌داری داده در volume آماده شده است.

### واگذاری ساختمان یا طبقه

فایل جدولی مرتبط را انتخاب کنید و بپرسید «کدام ساختمان یا طبقه را به ترتیب پس بدهم که همه سیت داشته باشند؟». این سؤال روی تمام ردیف‌های ذخیره‌شده محاسبه می‌شود و به اتصال مدل احتیاج ندارد. فایل‌هایی که قبلاً بارگذاری شده‌اند هم قابل استفاده‌اند.

در گزارش تعدادی، هر ردیف باید یک گروه مستقل باشد و دو مقدار از ظرفیت قابل استفاده، تعداد افراد نیازمند سیت و سیت خالی را داشته باشد. در گزارش صندلی‌به‌صندلی، هر ردیف باید یک صندلی باشد و وضعیت اشغال یا شخص مستقر را مشخص کند. نام ساختمان لازم است. برای برنامه طبقات، طبقه هر ردیف هم لازم است. در صورت تفاوت نام ستون‌ها، از «بررسی و تنظیم ستون‌های محاسبه» در پاسخ استفاده کنید. انتخاب‌ها برای همان فایل در مرورگر ذخیره می‌شوند.

معیار، بیشترین تعداد ساختمان یا طبقه قابل واگذاری است، به فرض یک سیت برای هر نفر و امکان جابه‌جایی آزاد. برنامه ساختمان و برنامه طبقه دو سناریوی مستقل هستند. هزینه اجاره و الزام به هم‌مکانی واحدها در این معیار لحاظ نمی‌شوند. اگر افراد فاقد صندلی هم به سیت نیاز دارند، از گزارش تعدادی با تعداد کل افراد استفاده کنید.

فونت وزیر نسخه ۳۰٫۱ در مسیر `public/fonts` قرار دارد. اپ فایل WOFF2 را محلی می‌خواند و فایل TTF برای نصب روی ویندوز در همان پوشه است.
